# Independent GTA highlight functional requirements

Version: 2026-10-25. This is the sole research handoff intended for an independent implementation context. It contains original behavioral requirements, no competitor source, proprietary internals, recovered algorithms, or copied visual assets. Implementation must use original MIT-licensed code, the authorized SDK, and documented dependencies. Thresholds below are proposed product acceptance criteria, not competitor measurements or demonstrated accuracy.

## Inputs and evidence

1. Accept existing host analysis, rather than requiring a new game client hook. Inputs may include timestamped speech/transcript, audio reactions, visual event descriptions, creator markers, and viewer nominations. Work without any optional signal, and report which modalities were available. Never label a transcript-only run multimodal.
2. Represent each evidence item with source modality, source timestamp/interval, text or factual observation, and confidence when available. Normalize finite timestamps to media seconds; reject invalid, negative, inverted, or out-of-range intervals. Preserve provenance through scoring and export.
3. A detected event is a supported observation, not a keyword match alone. Mentions such as 'remember that crash yesterday' must not assert a crash now. Conditional, negated, and hypothetical statements require corroboration or a review flag. Audio volume, repeated punctuation, profanity, laughter, or chat frequency alone must not establish a vehicle crash, chase, stunt, or violent event.

## Independent event taxonomy

4. Classify supported candidates into vehicle incident, pursuit/escape, stunt attempt, NPC/environment surprise, dialogue payoff, roleplay scene, unexpected failure, or creator reaction. Categories may overlap; a single underlying incident must not multiply the output count. Include a general noteworthy-gameplay fallback only with specific evidence. Avoid game-version-specific HUD assumptions.
5. Preserve event structure: setup establishes context, action contains the actual incident/payoff, and reaction supplies a relevant aftermath when present. Record action start/end separately from selected clip boundaries. A pursuit with no escalation or payoff is lower priority than a complete incident; quiet dialogue must remain eligible.
6. For dialogue and roleplay, include the question/premise and punchline or resolution as a complete utterance when available. A reaction without an identified gameplay cause may be a creator-reaction category, but its title must not invent that cause.

## Timing and duration

7. Produce clip boundaries satisfying 0 <= start < end <= media duration. Always contain the supported action/payoff. Proposed default desired duration is 15–60 seconds, configurable within host limits. The short-media case is permitted to be shorter. If an event cannot fit, flag truncation or require review; do not silently cut the payoff.
8. Where relevant source material exists, target at least 3 seconds of preceding setup and 3 seconds of aftermath; extend to utterance or event boundaries. Permit up to 12 seconds of lead-in and 10 seconds of reaction by default. These are independently chosen starting values, not claims about optimal entertainment duration. Avoid padding with unrelated silence merely to meet a target duration.
9. If a user requests a duration that cannot contain action and relevant reaction, explain the constraint in review metadata. A late reaction belonging to another event must not be appended solely because it is loud.

## Ranking and duplicate control

10. Rank using explicit, separately inspectable evidence for event relevance, setup/payoff completeness, reaction, novelty, and available corroboration. Store a score breakdown and reason text. Do not expose a score as predicted views, calibrated probability, or proof of virality. Missing modalities must not masquerade as positive evidence.
11. Loudness-only fixture: sustained gunfire/music/shouting without event or dialogue evidence produces no auto-selected gameplay event. Dialogue-only fixture: a coherent, supported low-volume dialogue payoff remains eligible. Nomination-only fixture: a marker can request analysis/review but cannot independently make an unsupported incident publishable.
12. Default duplicate rule: candidates from the same source with temporal intersection divided by shorter duration >= 0.65 are treated as one incident unless distinct action evidence is recorded. Also deduplicate repeated identical semantic evidence with nearby action centers (proposed 10 seconds). Retain the strongest complete candidate or merge compatible evidence within duration limits; preserve reasons for suppression.
13. Final ordering is deterministic for equal inputs and configuration; define stable tie-breaking. Respect requested top-N and return fewer than N rather than filling with unsupported events. Support category filters and prevent one incident appearing under several categories in the same digest.

## Factual presentation and editing

14. Every output includes factual title, event category, selected start/end, action interval, evidence references, score explanation, available modalities, and review warnings. Titles describe only supported actions. Do not invent outcomes, wanted levels, characters, quotations, locations, game versions, or 'world record' claims. Prefer a neutral fallback such as 'Vehicle incident and reaction' to a more specific unsupported claim.
15. Present candidates for review with preview/source seek, title editing, boundary adjustment, keep/reject controls, and export selection where the host supports them. Preserve source/session association. Clearly distinguish analysis-only metadata from rendered footage.
16. Vertical export must preserve the main action and readable relevant context. Use existing host framing controls. When subject tracking is absent or uncertain, offer letterboxing, split layout, or manual framing instead of claiming action-aware cropping. Facecam must not displace the gameplay payoff. Test framing on exported frames, not just crop coordinates.
17. Captions are optional and editable. Use only available transcript words; preserve timing and do not fabricate dialogue. Review names, overlapping speech, and uncertain transcription. Avoid covering key gameplay/HUD areas. Do not describe captions as implemented unless a rendered output has been inspected.
18. Download/share/publish actions use host integrations and explicit settings. External automatic posting is opt-in. Keep source timestamp links and optional native clips separate from local media exports. Media-relative and platform-relative time require an explicit mapping; never assume local file start equals VOD start.

## Evaluation and honest release status

19. Unit/contract fixtures must cover a crash with lead-in and late reaction, quiet dialogue with a punchline, pursuit with no payoff, negated/historical mentions, loud non-events, repeated analysis of one incident, overlapping distinct actions, malformed times, short media, missing modalities, and factual-title fallback. Synthetic fixtures validate rules only and are not video accuracy benchmarks.
20. Real quality comparison requires authorized footage and a rights/provenance manifest. Use the same media, transcript/cache, model configuration, clip limits, and rubric for baseline and plugin runs. Record input hashes, configuration, output intervals, exported clip paths, and human review results. Public video links without processing permission may inform reference notes but must not become test downloads.
21. For each video case, annotate setup/action/reaction intervals and expected factual event before running the comparison. Report event precision/recall where annotations support it, fraction of clips retaining full action, relevant setup/reaction inclusion, duplicate rate, misleading-title count, and measured duration. Review visual framing, audio and captions from actual exports.
22. Score relevance, hook, setup/payoff completeness, reaction inclusion, framing, audio clarity, duration, caption quality, duplicate prevention, and watchability on 1–5. Anchor 1 as absent/incorrect/unusable, 3 as usable with material edits, and 5 as complete/accurate/ready for the stated task; define 2/4 as intermediate. Use not-applicable for absent reaction/captions; exclude those dimensions from aggregates. Log at least one concrete reason per score, reviewer identity/role, and disagreements. Engagement counts describe context only.
23. Require zero fabricated claims in reviewed titles, zero invalid clip intervals, and zero duplicate incidents under the configured rule on the acceptance fixtures. Proposed initial real-footage target: >=90% full-action retention among selected annotated incidents and <=10% duplicate incidents; report sample size and uncertainty rather than converting a small sample to a broad accuracy claim. Other quality thresholds require a baseline before claiming improvement.
24. A completed benchmark requires baseline and updated exported videos, identical cases, scores, and a documented comparison. Without authorized GTA footage or export capability, mark video benchmarking pending; do not infer improved entertainment quality from passing metadata tests.
25. Treat established GTA-like event categories as readiness scaffolding. Do not claim GTA VI detection accuracy, tested console capture, or release readiness without authentic authorized footage and actual tests. Record game/version/capture platform for every real test. Keep event taxonomy configurable for later footage.

## Implementation boundary

The implementer should read only this document from the research directories, inspect authorized host/SDK contracts independently, and design its own code and scoring. Do not ingest dirty-room notes, REA output, competitor assets, or external implementation source. Any further research-derived requirements should enter as revised behavior statements with provenance kept separately. This workflow separates research and implementation contexts; it is not a legal guarantee about independent creation.
